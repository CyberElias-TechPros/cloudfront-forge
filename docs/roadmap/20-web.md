# 20 — Web workstream (WEB)

**Purpose:** take the existing SPA from "works and is honest" to _fast, inclusive, discoverable,
measurable, and conversion-shaped_ — and to make it the acquisition + billing surface for the
Android app rather than a competing product.

**Positioning rule for every task here:** the web is the **public shopfront, the account and
billing console, and the desktop experience**. Android is the primary daily-use surface. When a
feature is better native (watching, notifications, queue), web either matches it cheaply or
hands off to the app with a deep link. Web must never be a stub.

**Master plan:** [../ROADMAP.md](../ROADMAP.md) · **Findings:** [00-audit-and-baseline.md](00-audit-and-baseline.md)

## Web acceptance criteria (definition of done for the workstream)

1. **Core loop parity:** sign in → join community → submit → watch → claim → review → mission,
   fully usable on a 360 px viewport over throttled 4G.
2. **Measured:** every step of the funnel has an event and a dashboard.
3. **Fast:** p75 LCP ≤2.5 s mobile, INP ≤200 ms, CLS ≤0.1, entry JS ≤150 kB gzip.
4. **Inclusive:** axe-clean critical paths, keyboard-complete, two themes at AA contrast, one
   non-English locale shipped.
5. **Discoverable:** ≥3 indexable content types, valid structured data, sitemap indexed.
6. **Monetizable and compliant:** consented ads, Stripe/Paystack billing, deletion and export
   reachable, pricing page live.
7. **Handoff:** installed app opens the correct screen from a shared link; web installs the app.
